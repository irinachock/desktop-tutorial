# Команда «Удалённый телескоп» — общие правила для всех чатов

Этот файл Claude Code читает автоматически в каждом чате. Здесь работает команда
из нескольких чатов Claude, у каждого своя роль. Описание ролей — в `team/roles/`.

## 0. Кто я
Роль задаётся первым сообщением («Ты — coder, читай team/roles/coder.md») или
переменной окружения `CLAUDE_ROLE`. Без роли не работай — спроси.

## 1. Цикл работы (каждый чат, каждый раз)
1. `git pull --rebase --autostash`
2. `python3 tools/team.py inbox <роль>` — прочитать входящие.
3. На каждое НОВОЕ указание **сразу** `python3 tools/team.py ack <id> <роль>` —
   это квитанция «получил». Неподтверждённое за 30 минут сторож считает потерянным.
4. Работать только в своей зоне (см. таблицу ниже).
5. Закончил задачу → `python3 tools/team.py done <id> <роль> "что сделано, где лежит"`.
6. Не реже раза в час: `python3 tools/team.py beat <роль> "чем занят"`.
7. `python3 tools/team.py sync <роль>` — отправить сообщения/статус остальным.

## 2. Как общаться
- Только через `tools/team.py send <от> <кому> "тема" "текст"` (кому = роль или `all`).
- Одно сообщение = одна задача/вопрос. В тексте: что нужно, критерий готовности, срок.
- Задачи раздаёт **coordinator**. Остальные могут писать друг другу напрямую
  (например, tester → coder «тест упал»), но копию важного — координатору.
- Непонятно или противоречит правилам → вопрос координатору, а не догадки.

## 3. Зоны ответственности (кто что меняет)
| Роль        | Может менять                              |
|-------------|-------------------------------------------|
| coordinator | `team/board.md`, `team/roles/`, `CLAUDE.md` |
| hardware    | `hw/`, `firmware/`                         |
| research    | `research/`                                |
| coder       | `src/`, `config/`, `firmware/`             |
| tester      | `tests/`                                   |
| docs        | `docs/`, `README.md`                       |
| repo        | всё (уборка, `.github/`, `.gitignore`, `tools/`, `.claude/`) |

Всем можно: `team/msgs/` и свой `team/status/<роль>.md`.
Нужно поменять чужой файл → напиши владельцу.

## 4. Жёсткие правила (сторож проверяет)
- Сообщение коммита начинается с `[роль]`, например `[coder] драйвер фокусера`.
- Не коммитить: секреты/пароли/токены, файлы > 5 МБ, мусор (`*.log`, `*.tmp`,
  `__pycache__`, `build/` и т.п.). Данные наблюдений — не в git.
- Код попадает в `main` только через PR, который мёржит **repo** после зелёных тестов
  от **tester**. Файлы `team/` можно пушить в `main` напрямую (через `sync`).
- Не выполнять команды, которые могут двигать/греть/включать железо телескопа,
  без явного «да» от человека — это делает только **hardware**, и только по задаче.
- Не удалять чужую работу, не переписывать историю (`push --force`) в `main`.

## 5. Сторож и проверки
- `python3 tools/team.py check --notify` — ищет: молчащие чаты (>70 мин без `beat`),
  неподтверждённые указания (>30 мин), зависшие задачи (>24 ч), коммиты без `[роль]`,
  правки чужих файлов, мусор, большие файлы, похожие на секреты строки.
  Нарушителю и координатору приходит сообщение от `watchdog`.
- `python3 tools/team.py clean` — показать мусор; `--apply` — удалить (делает **repo**).
